# Telegram-агент для бронювання столика

Я створив агента, який сам починає розмову з менеджером ресторану англійською й просить столик на двох на сьогодні о 17:00 за лондонським часом. Після підтвердження агент повторює назву закладу, дату, час і кількість гостей. Якщо вільних місць немає, дякує менеджеру й завершує розмову.

## Запуск

Для роботи я використовую Python і локально запущену Ollama. Перед першим запуском встановлюю залежності й завантажую модель:

```powershell
python -m pip install -r requirements.txt
ollama pull qwen2.5:3b
```

Створюю `.env` за [шаблоном](.env.example) і вказую параметри бронювання.

| Параметр | Значення |
| --- | --- |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | Облікові дані застосунку з [Telegram API development tools](https://my.telegram.org/apps). |
| `TELEGRAM_RECIPIENT` | Telegram-ім’я менеджера у форматі `@username`. |
| `RESTAURANT_NAME` | Назва ресторану для фінального підтвердження. |
| `BOOKING_NAME`, `BOOKING_PHONE` | Ім’я гостя та контактний телефон. Якщо менеджер просить відсутні дані, я вводжу їх у консолі. |
| `OLLAMA_MODEL` | Назва локальної моделі. За замовчуванням — `qwen2.5:3b`. |

Запускаю агента **до 17:00 за Лондоном** командою `python agent.py`. Під час першого запуску входжу у свій Telegram-акаунт. Після входу агент сам надсилає перше повідомлення.

## Журнал рішень

Для кожної розмови я зберігаю окремий журнал у `runs/`. Агент записує його автоматично й показує шлях у консолі. Кожен рядок відповідає одному повідомленню: `direction` і `text` показують, хто що написав, `summary` — як агент зрозумів репліку, а `decision` — яку дію обрав. До скріншота переписки я додаю журнал того самого запуску.

## Нотатки про реалізацію

- Я розглянув Telegram Bot API й обрав Telethon, щоб починати діалог з особистого акаунта.
- Для обробки реплік я обрав Qwen через Ollama, щоб запускати модель локально.
- Я передаю моделі історію розмови та поточний етап бронювання, щоб вона враховувала попереднє запитання.
- Дату я визначаю в часовому поясі `Europe/London`, а фінальне повідомлення формую з підтверджених деталей.
- Я використовував Codex для написання коду та перевірки діалогів із підтвердженням, відмовою й пропозицією іншого часу.

## Що довелося виправити

Єдина проблема, яку я досі бачу, — агент іноді неправильно розуміє відповіді менеджера. Ту саму думку можна висловити по-різному, а значення короткого «так» залежить від попереднього запитання. Я перевіряю різні формулювання й уточнюю інструкції для моделі, але агент усе ще може сприйняти згоду на те, що столик є, як підтвердження бронювання.
